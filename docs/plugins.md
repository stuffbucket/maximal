# Claude Code integration

`maximal app claude-code --enable` writes `env.ANTHROPIC_BASE_URL`, `env.CLAUDE_CODE_AUTO_MODE_SERVER=0`, an `apiKeyHelper` command, and catalog-resolved fast/capable model defaults into `~/.claude/settings.json` (`src/apps/claude-code/`). `CLAUDE_CODE_AUTO_MODE_SERVER=0` disables only Claude Code's server-side **permission** Auto review, which Copilot doesn't support; it leaves both the local permission classifier and the local **model-tier** Auto classifier active. The helper prints the Claude Code API-client key from Settings → API clients, falling back to the default endpoint key. (The same key is available on demand via `maximal api claude-code`.)

- **Stable echo helper, not a versioned binary path.** The `apiKeyHelper` value emits the resolved key directly: `echo '<key>'` through `/bin/sh -c` on macOS/Linux, or a base64-decoding `powershell.exe` command through `cmd.exe` on Windows (where POSIX single quotes are literal). Maximal records an exact-command SHA-256 fingerprint in `_maximalHelper`; a matching marker proves ownership, while an unmarked echo command or edited marked command is left untouched. API-key create/update/delete refreshes an enabled owned helper immediately. Binary-backed `"<abs-path-to-maximal>" api claude-code`, Bun runtime, and legacy `--apiKeyHelper claude-code` forms are recognized as pre-v0.4.42 maximal artifacts and migrated to the stable strategy on the next boot/apply.
- **Catalog-driven model tiers, with explicit overrides.** Claude Code decides locally whether a request belongs to its fast/Haiku tier or capable/Sonnet tier; Maximal only assigns the concrete IDs via `ANTHROPIC_DEFAULT_HAIKU_MODEL` and `ANTHROPIC_DEFAULT_SONNET_MODEL`. Settings → Models can pin either tier. Without a pin, fast prefers an eligible Haiku, then small GPT, then another GPT; capable prefers an eligible Sonnet, then full-size GPT, then small GPT. Eligible means picker-visible, non-variant, tool-calling, streaming, and routable from Messages ingress. Successful catalog refreshes reconcile owned automatic choices. A direct edit or deletion in Claude Code becomes externally owned; deliberately choosing that tier in Maximal Settings snapshots the external state and takes ownership again. Missing overrides remain visible but are not substituted; no match leaves the key unset for Claude Code's own default.
- **Reverts to the prior state on disable.** Toggling Claude Code off restores `env.ANTHROPIC_BASE_URL`, `apiKeyHelper`, and both model-tier defaults to exactly what was there before maximal first wrote them (or removes them if they were absent), via a `_maximalPrior` snapshot maximal stores in the file. `_maximalAutoModels` records the exact tier values Maximal last wrote, so a later direct edit is recognized as user-owned and survives reapply and revert. `CLAUDE_CODE_AUTO_MODE_SERVER` is added only when absent and removed only when the snapshot proves Maximal added it and its value is still `"0"`; existing values and later user edits survive. A pre-existing *foreign* `apiKeyHelper` / base URL is never overwritten in the first place — enable refuses with a conflict surfaced in Settings → Apps.
- **Subagent detection** reads a `__SUBAGENT_MARKER__` inside `<system-reminder>`, or the opt-in `x-claude-code-request-class` / `x-claude-code-agent-type` hint headers (see `docs/architecture.md` → request flow). This repo ships no Claude Code or Opencode plugin that injects the marker.
