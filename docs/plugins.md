# Claude Code integration

`maximal app claude-code --enable` writes `env.ANTHROPIC_BASE_URL`, `env.CLAUDE_CODE_AUTO_MODE_SERVER=0`, an `apiKeyHelper` command, catalog-resolved Haiku/Sonnet alias mappings, and a client-side Auto permission classifier into `~/.claude/settings.json` (`src/apps/claude-code/`). `CLAUDE_CODE_AUTO_MODE_SERVER=0` disables Claude Code's server-side permission review, which Copilot doesn't support, so `CLAUDE_CODE_AUTO_MODE_MODEL` controls the local classifier instead. The helper prints the Claude Code API-client key from Settings → API clients, falling back to the default endpoint key. (The same key is available on demand via `maximal api claude-code`.)

- **Stable echo helper, not a versioned binary path.** The `apiKeyHelper` value emits the resolved key directly: `echo '<key>'` through `/bin/sh -c` on macOS/Linux, or a base64-decoding `powershell.exe` command through `cmd.exe` on Windows (where POSIX single quotes are literal). Maximal records an exact-command SHA-256 fingerprint in `_maximalHelper`; a matching marker proves ownership, while an unmarked echo command or edited marked command is left untouched. API-key create/update/delete refreshes an enabled owned helper immediately. Binary-backed `"<abs-path-to-maximal>" api claude-code`, Bun runtime, and legacy `--apiKeyHelper claude-code` forms are recognized as pre-v0.4.42 maximal artifacts and migrated to the stable strategy on the next boot/apply.
- **Catalog-driven model defaults, with explicit overrides.** `ANTHROPIC_DEFAULT_HAIKU_MODEL` and `ANTHROPIC_DEFAULT_SONNET_MODEL` map Claude Code's Haiku and Sonnet aliases to concrete catalog IDs; they are not an Auto task router. Without a pin, the Haiku mapping prefers an eligible Haiku, then small GPT, then another GPT; the Sonnet mapping prefers an eligible Sonnet, then full-size GPT, then small GPT. `CLAUDE_CODE_AUTO_MODE_MODEL` independently selects the model for client-side Auto permission checks. Its automatic choice prefers a supported Haiku, then the configured GPT session model, then other GPT models. Settings → Models can pin any of the three. Eligible means picker-visible, non-variant, tool-calling, streaming, and routable from Messages ingress; classifier choices additionally exclude Claude versions that Claude Code ignores for permission review. Successful catalog refreshes reconcile owned automatic choices. A direct edit or deletion in Claude Code becomes externally owned; deliberately choosing that setting in Maximal snapshots the external state and takes ownership again. Missing overrides remain visible but are not substituted. Alias mappings with no match leave their keys unset for Claude Code's defaults. An owned classifier fails closed: it keeps a temporarily missing compatible model so it can resume if the model returns, replaces a still-cataloged but incompatible model with an unavailable sentinel, and uses that sentinel when the person explicitly reclaims Automatic before a compatible model exists.
- **Reverts to the prior state on disable.** Toggling Claude Code off restores `env.ANTHROPIC_BASE_URL`, `apiKeyHelper`, both alias mappings, and the Auto permission classifier to exactly what was there before maximal first wrote them (or removes them if they were absent), via a `_maximalPrior` snapshot maximal stores in the file. `_maximalAutoModels` records the exact values Maximal last wrote, so a later direct edit is recognized as user-owned and survives reapply and revert. An ordinary quit or in-place update restores the active settings but retains that model ownership in a dormant `_maximalAutoModelsJournal`; the next boot resumes owned Automatic and explicit choices while preserving direct edits or deletions made before or during the stop. Explicit disable removes the journal. `CLAUDE_CODE_AUTO_MODE_SERVER` is added only when absent and removed only when the snapshot proves Maximal added it and its value is still `"0"`; existing values and later user edits survive. A pre-existing *foreign* `apiKeyHelper` / base URL is never overwritten in the first place — enable refuses with a conflict surfaced in Settings → Apps.
- **Not installed yet.** When no install is found, Settings → Apps shows the install command for the platform. macOS and Linux keep `curl -fsSL https://claude.ai/install.sh | sh`. Windows shows Anthropic's PowerShell installer, `irm https://claude.ai/install.ps1 | iex` ([setup](https://code.claude.com/docs/en/setup)). When `winget` runs, Windows also offers **Install with WinGet**. After a confirm, Maximal starts `winget install --id Anthropic.ClaudeCode --exact --source winget --silent --disable-interactivity` in the background: an argument vector with no shell, no elevation, and no `--ignore-security-hash` or `--accept-package-agreements`. It streams WinGet's output, then re-detects Claude Code, including WinGet's `Links` folder, which a running Maximal's PATH doesn't yet show. Routing stays off until switched on. The PowerShell installer isn't run by Maximal, since it executes a script with no pinned hash. (`src/apps/claude-code/install.ts`)
- **Subagent detection** reads a `__SUBAGENT_MARKER__` inside `<system-reminder>`, or the opt-in `x-claude-code-request-class` / `x-claude-code-agent-type` hint headers (see `docs/architecture.md` → request flow). This repo ships no Claude Code or Opencode plugin that injects the marker.
