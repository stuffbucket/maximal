# App integrations and Claude Code

## Apps surface

Settings → Apps presents each integration as a compact row with one end-to-end status: **Working** when Maximal owns and has applied the route, **Off** when the app is available but routing is disabled, **Not found** when detection cannot find the app, and **Needs attention** when ownership or cleanup prevents the requested state. Selecting a missing app asks for confirmation, then opens that app’s official setup and download instructions. Maximal does not proactively install it or run an installer; after the app is installed, detection finds it and the person can enable routing.

Routing ownership is profile-aware. A Maximal profile reconciles and reverts only markers it owns, including during boot and shutdown, so two development profiles that share an app’s user configuration do not flap the route as either profile starts or stops. A valid marker owned by another Maximal profile or copy is reported separately and can be replaced only through the explicit override confirmation. That override transfers Maximal’s routing ownership and stops the other copy from managing the app. It is not a general force option: foreign, malformed, incomplete, or user-edited configuration is preserved and still refused. The one deliberate exception is Claude Desktop's **Take over** (below), which switches Claude away from another gateway without changing it.

## Claude Desktop ownership

Settings names the app **Claude**, as Anthropic does, in its Harnesses row and its Connect, transfer and Take over dialogs; the `claude-desktop` id, API-key label and `Claude-3p` paths are unchanged.

Claude Desktop routing is a `maximal` entry in Desktop's config library (`Claude-3p/configLibrary/`) plus a `maximal-routing.json` marker beside it, which records the profile id, a SHA-256 fingerprint of the profile as Maximal wrote it, the prior selection, and (since profile ownership) `version: 2` with the owning Maximal profile's id. A marker without an owner, written by an older build, is attributed by comparing the profile's gateway URL with this copy's.

Desktop rewrites library profiles in its own formatting (two-space JSON, no trailing newline) and can write an earlier profile's values back over the applied one. So the marker's profile still counts as Maximal's when either:

- its parsed content, serialized the way Maximal writes it, matches the fingerprint (a reformat, possibly with keys reordered); or
- it is exactly a Maximal artifact: the entry is named `maximal`, the profile has exactly the fields Maximal writes, every field except the gateway URL and key equals this copy's values, the URL is `http://127.0.0.1:<port>`, and the URL and key pair is either this copy's own or another `maximal` entry's in the library.

Ownership then follows the marker: this profile's marker is reapplied normally; another profile's, a dead profile's, or an ownerless marker on another port is offered through the explicit transfer, which rewrites that same entry in place. Anything else on the marker's profile, such as another gateway or key, a changed folder or flag, an added field, or a renamed entry, is the user's: it is reported as a gateway set up by the user or another tool and is never overwritten, transferred, or deleted.

**Take over.** When Claude is on a readable gateway profile Maximal doesn't own (`foreign-gateway-profile`), the Connect dialog ("Connect Claude") says Maximal found another gateway and didn't change it. **Close** is the default; **Take over** sends `overrideForeignGateway: true` (Settings only). That applies Maximal's own entry, never writes the other profile, and snapshots the other selection and the top-level keys Maximal sets, so disabling switches back exactly. It is one-shot: boot never repeats it if Claude is later switched back. It does not bypass an unreadable or unsafely named applied profile, an unreadable `_meta.json`, a malformed marker, or another Maximal profile's ownership, which keep their own refusals.

## Claude Code integration

`maximal app claude-code --enable` writes `env.ANTHROPIC_BASE_URL`, `env.CLAUDE_CODE_AUTO_MODE_SERVER=0`, an `apiKeyHelper` command, the current catalog-resolved Haiku/Sonnet selections, and a client-side Auto permission classifier into `~/.claude/settings.json` (`src/apps/claude-code/`). `CLAUDE_CODE_AUTO_MODE_SERVER=0` disables Claude Code's server-side permission review, which Copilot doesn't support, so `CLAUDE_CODE_AUTO_MODE_MODEL` controls the local classifier instead. The helper prints the Claude Code API-client key from Settings → API clients, falling back to the default endpoint key. (The same key is available on demand via `maximal api claude-code`.) The toggle owns only this client setup and its plugin MCP projections; root Anthropic Messages resolves the saved Haiku/Sonnet aliases for every caller even when the integration is off.

- **Stable echo helper, not a versioned binary path.** The `apiKeyHelper` value emits the resolved key directly: `echo '<key>'` through `/bin/sh -c` on macOS/Linux, or a base64-decoding `powershell.exe` command through `cmd.exe` on Windows (where POSIX single quotes are literal). Maximal records an exact-command SHA-256 fingerprint in `_maximalHelper`; a matching marker proves ownership, while an unmarked echo command or edited marked command is left untouched. API-key create/update/delete refreshes an enabled owned helper immediately. Binary-backed `"<abs-path-to-maximal>" api claude-code`, Bun runtime, and legacy `--apiKeyHelper claude-code` forms are recognized as pre-v0.4.42 maximal artifacts and migrated to the stable strategy on the next boot/apply.
- **Catalog-driven model defaults, with explicit overrides.** The selections live under `anthropicMessages` in Maximal config, not under Claude Code's integration toggle. Root `/v1/messages` and `/v1/messages/count_tokens` use the Haiku/Sonnet selections directly; an enabled integration additionally writes them as `ANTHROPIC_DEFAULT_HAIKU_MODEL` and `ANTHROPIC_DEFAULT_SONNET_MODEL`. They are not an Auto task router. Without a pin, the Haiku mapping prefers an eligible Haiku, then small GPT, then another GPT; the Sonnet mapping prefers an eligible Sonnet, then full-size GPT, then small GPT. `CLAUDE_CODE_AUTO_MODE_MODEL` independently selects the model for Claude Code's client-side Auto permission checks and is never inferred from generic Messages traffic. Its automatic choice prefers a supported Haiku, then the configured GPT session model, then other GPT models. Settings → Models can pin any of the three. Eligible means non-embeddings, non-variant, tool-calling, streaming, and routable from Messages ingress, whether or not Copilot shows the model in its picker; classifier choices additionally exclude Claude versions that Claude Code ignores for permission review. Successful catalog refreshes reconcile owned automatic choices. A direct edit or deletion in Claude Code becomes externally owned; deliberately choosing that setting in Maximal snapshots the external state and takes ownership again. Missing overrides remain visible but are not substituted. Alias mappings with no match leave their Claude Code keys unset for its defaults. An owned classifier fails closed: it keeps a temporarily missing compatible model so it can resume if the model returns, replaces a still-cataloged but incompatible model with an unavailable sentinel, and uses that sentinel when the person explicitly reclaims Automatic before a compatible model exists. Legacy app-scoped model fields remain readable and migrate on the next Models settings write.
- **Reverts to the prior state on disable.** Toggling Claude Code off restores `env.ANTHROPIC_BASE_URL`, `apiKeyHelper`, both alias mappings, and the Auto permission classifier to exactly what was there before maximal first wrote them (or removes them if they were absent), via a `_maximalPrior` snapshot maximal stores in the file. `_maximalAutoModels` records the exact values Maximal last wrote, so a later direct edit is recognized as user-owned and survives reapply and revert. An ordinary quit or in-place update restores the active settings but retains that model ownership in a dormant `_maximalAutoModelsJournal`; the next boot resumes owned Automatic and explicit choices while preserving direct edits or deletions made before or during the stop. Explicit disable removes the journal. `CLAUDE_CODE_AUTO_MODE_SERVER` is added only when absent and removed only when the snapshot proves Maximal added it and its value is still `"0"`; existing values and later user edits survive. A pre-existing *foreign* `apiKeyHelper` / base URL is never overwritten in the first place — enable refuses with a conflict surfaced in Settings → Apps.
- **Not found yet.** A missing Claude Code install follows the shared Apps flow: the compact row shows **Not found**, and opening it presents a confirmation that links to Claude Code’s official setup and download instructions ([setup](https://code.claude.com/docs/en/setup)). Maximal does not run WinGet, a shell command, or any other installer. Routing remains off until detection finds Claude Code and the person explicitly switches it on.
- **Subagent detection** reads a `__SUBAGENT_MARKER__` inside `<system-reminder>`, or the opt-in `x-claude-code-request-class` / `x-claude-code-agent-type` hint headers (see `docs/architecture.md` → request flow). This repo ships no Claude Code or Opencode plugin that injects the marker.
